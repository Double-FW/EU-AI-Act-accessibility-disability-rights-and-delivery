# Weekly GitHub to Hugging Face publication: complete setup

Source: https://github.com/Double-FW/EU-AI-Act-accessibility-disability-rights-and-delivery

Destination: https://huggingface.co/datasets/GarethFW/EU_AI_Act_accessibility_disability_rights_and_delivery

The destination already exists. This setup publishes exact approved source documents and sections with traceable metadata. It does not create a dataset or train an LLM. Complete every step below, in order. Never share a token in chat or a screenshot.

## 1. Confirm the source and destination

1. Check the source and destination links above. Their spelling is intentional and must match the existing repositories.
2. The committed `huggingface/export-config.json` already sets the exact destination. No `HF_DATASET_ID` GitHub variable is needed for this workflow.
3. Check that the sync files and `.github/workflows/huggingface-sync.yml` are on the default **main** branch before trying to run it.

## 2. Create a dataset-specific Hugging Face token

1. Sign into the **GarethFW** account at https://huggingface.co.
2. Open https://huggingface.co/settings/tokens.
3. Choose **Create new token**. Select **Fine-grained**, or **Custom** if the page shows permission presets.
4. Name it `EU-AI-Act-GitHub-sync`.
5. Find **Repositories permissions**, the section for selected repositories. Select only `GarethFW/EU_AI_Act_accessibility_disability_rights_and_delivery`.
6. Enable **Read contents of selected repos** and **Write contents/settings of selected repos** for that selection. The interface may automatically select related gated-request permissions. Keep the repository selection limited to this dataset.
7. No user-wide write, billing, inference or job permissions are needed. Do not select those for this sync.
8. Create the token and copy its full value. Keep this page available until the next step is complete. If the value is no longer available, create a replacement and revoke the unused token.

## 3. Save the token in GitHub

1. Open https://github.com/Double-FW/EU-AI-Act-accessibility-disability-rights-and-delivery/settings/secrets/actions.
2. Under **Repository secrets**, choose **New repository secret**.
3. Set **Name** to exactly `HF_TOKEN` — an underscore, not a hyphen.
4. Paste the full token into the **Secret** field, without spaces or line breaks before or after it.
5. Choose **Add secret**. Check that `HF_TOKEN` appears in the list. GitHub hides its value afterwards; that is expected.
6. If `HF_TOKEN` already exists, update it rather than trying to create the same name again. An existing credential can be reused only if it has write access to this exact dataset. Repository permissions are edited in Hugging Face.

## 4. Run the first sync

1. Open https://github.com/Double-FW/EU-AI-Act-accessibility-disability-rights-and-delivery/actions/workflows/huggingface-sync.yml.
2. Choose **Run workflow**. Leave the branch as **main**.
3. Choose the green **Run workflow** button in that menu.
4. Open the new run and wait for the tests, build and publish steps to finish.
5. All three stages must succeed. A successful build alone does not confirm publication.
6. If it fails, inspect the failed step/log or share the run URL. Never share the token. A 403 can indicate missing write permission for this selected dataset. A whitespace error requires saving a clean token copy.

## 5. Confirm the Hugging Face result

1. Open https://huggingface.co/datasets/GarethFW/EU_AI_Act_accessibility_disability_rights_and_delivery/tree/main.
2. Confirm these seven managed files are present: `README.md`, `LICENSE`, `documents.jsonl`, `knowledge_chunks.jsonl`, `provenance.json`, `record_schema.json`, `validation_report.json`.
3. `.gitattributes` is expected and is retained. Other existing unmanaged files are also retained.
4. Open `provenance.json`. Its `source_repository` must be `Double-FW/EU-AI-Act-accessibility-disability-rights-and-delivery`. Its `source_commit` must match the GitHub run's source revision.
5. Confirm the generated dataset card describes the two views and the limits of this secondary regulatory material. The card is generated by the sync; edit the exporter to make lasting changes to it.
6. Check the dataset viewer loads the `knowledge_chunks` and `documents` configurations. Loading is separate from training a model.

## 6. Weekly use

The workflow runs on **Mondays at 08:27 UTC**, as well as on manual request. GitHub can delay scheduled jobs or disable them after public-repository inactivity. Make authoring changes in GitHub. Publication is one-way; edits made only to managed Hugging Face files can be replaced by the next sync. Dataset visibility stays unchanged.

The exporter reads committed HEAD, including its configuration. The explicit allow-list contains 24 required Markdown sources plus the root MIT licence. The full research analysis and eight delivery guides also become exact H1/H2 sections. Navigation, governance/adoption/contribution guidance, dated source registers, validation history and seven blank templates remain complete-document only. All source dates, evidence limits, tables and subordinate workflow descriptions remain intact.

`examples/worked-scenarios.md` is excluded from both views and retained in GitHub. Illustrations are not actual test, participant or legal evidence. Change history, setup, sync code, tests and automation are maintenance material and are also excluded. The source analysis is a separate original research document, not a combined RAG snapshot. Its checksum is checked against `sources/research-basis.md`.

Each record carries exact source/governance, scope/surface, dated legal/standards, Double FW routing, adoption, result-vocabulary and analysis-interpretation context. Twelve workflow descriptions, eighteen AI-A local scenarios and thirty-six AI-O obligation routes retain their own identities. They are not canonical WCAG/ACT test IDs, deployed integrations or executed tests. Templates remain blank; organisational adoption, actual authority and service evidence remain separate.

The source legal/research reference date is **11 November 2026**. Publication preserves that date. External linked law, standards and other Double FW repositories are not fetched or rechecked. A weekly upload is not a weekly legal review.

## 7. Maintainer checks

After committing source/configuration changes, run from the repository root:

```bash
python -m pip install -r huggingface/requirements.txt
python -m unittest discover -s tests -p 'test_ai_act_huggingface.py' -v
python scripts/export_huggingface.py --output ../eu-ai-act-export-check
```

Output must be outside the checkout. Tests use mocked publication and require no token. Missing required files or interpretive context, unsafe paths, changed licence, invalid metadata, changed research provenance, unexpected stable-ID inventories or private-access metadata block export. Publication checks the source remains public, verifies the export inventory/checksums and rejects foreign-source destination provenance. It publishes changed managed files in one commit guarded by the destination revision. It never creates a repository, changes its visibility, removes unmanaged files or executes source examples.
